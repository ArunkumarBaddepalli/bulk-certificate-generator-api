How it works

The three decisions the backend is built around.

202
Accept now, generate later

POST /jobs returns a job id immediately. Generation runs after the response via BackgroundTasks; the client polls GET /jobs/{id}.

1:1
Per-recipient isolation

Each row is validated and rendered in its own try/except. One bad email or one renderer crash marks one row FAILED — the rest finish.

=
Safe to retry

An Idempotency-Key is stored with a UNIQUE constraint. The same key returns the same job with 200, even under concurrent requests.
